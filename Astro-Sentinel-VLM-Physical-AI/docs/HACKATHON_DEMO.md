# Astro-Sentinel VLM Droid — Physical AI demo plan

## Suggested 90-second live demo

1. **0–10 s — Show the active-camera indicator.** Explain that a pulsing camera glyph on the VENTUNO Q matrix means the USB camera is delivering fresh frames. Show that the camera's images are handled by the local VLM.
2. **10–25 s — Present an everyday object.** Bring a cup or another object supported by the selected VLM within 300 mm of the distance sensor. The matrix sweeps while the local VLM writes a concise text label.
3. **25–40 s — Show the perception/reasoning split.** The console prints the label (for example, `blue ceramic mug`). Only that text plus distance is sent to Nebius. The matrix spins during Nemotron reasoning.
4. **40–55 s — Demonstrate embodied response.** Nemotron picks HAPPY/CURIOUS/CONFUSED. Show matching face animation, buzzer chirps, and vibration pulse.
5. **55–70 s — Continuous interaction.** While the object stays within range, rotate or replace it. The local VLM labels again on the configured interval; a new label can lead to a new mood/reaction without moving the object to 450 mm.
6. **70–80 s — Show reset and camera status.** Move the object beyond 360 mm. Astro-Sentinel returns to idle while the camera-active glyph keeps pulsing.
7. **80–90 s — Explain privacy.** A single local temporary JPEG under the app-local runtime folder is used only for VLM inference and deleted immediately when inference returns, before the cloud call. Nebius receives text label + distance only—never the image.

## What to test before recording

- [ ] VLM Brick configured to local Qwen 3-VL-8B VLM and the model completes inference.
- [ ] Camera-active marker pulses while fresh camera frames arrive and changes to a crossed-camera glyph after loss of frames.
- [ ] At least 5 test objects produce reasonable short labels; unknown/low-information scenes produce `unknown`.
- [ ] Nemotron output parser accepts only HAPPY/CURIOUS/CONFUSED and safely falls back when offline.
- [ ] Distance enter/exit hysteresis works (300 mm entry, 360 mm exit).
- [ ] Continuous recaption uses a single worker and does not pile up requests while one inference is still running.
- [ ] A late VLM/cloud result after the object leaves does not trigger stale haptics or buzzer feedback.
- [ ] API key and local `.env` are not included in the public repository or demo footage.
- [ ] Submission video includes at least a minute of actual hardware operation, not just screenshots or slides.

## Claims to demonstrate

- Local VLM produces a label from the Arduino USB Camera image.
- The board matrix visibly indicates when fresh camera frames are arriving.
- Only the generated label and the distance are sent to Nebius Token Factory.
- Nemotron's returned mood controls a fixed set of local physical feedback patterns.
- A cloud error falls back locally rather than terminating the sensor loop.

## Known limitations to mention

- VLM latency and label quality depend on the local model selected and lighting/scene composition.
- The current VLM Brick API uses a local temporary JPEG path; the file is deleted after inference but exists briefly on local storage.
- The prompt/sanitizer avoids person-oriented labels and selected sensitive document/card categories best-effort; it is not a certified anonymization mechanism.
- A label generated by a VLM is an estimate and may be wrong. The model only selects gentle, non-safety-critical expressive feedback.
